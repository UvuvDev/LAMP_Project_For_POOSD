# LAMP on GCP — Terraform + Ansible

A from-scratch template that stands up a classic **L**inux / **A**pache / **M**ariaDB / **P**HP
server on Google Cloud. Terraform owns the cloud resources; Ansible owns everything
inside the VM.

```
infra/
├── Makefile                  # one-command workflows
├── terraform/                # VPC, firewall, static IP, service account, VM
│   ├── main.tf               # locals + project API enablement
│   ├── network.tf            # VPC, subnet, external IP, firewall rules
│   ├── compute.tf            # service account, IAM, the web VM
│   ├── inventory.tf          # renders ansible/inventory/hosts.ini
│   ├── variables.tf outputs.tf versions.tf
│   └── terraform.tfvars.example
└── ansible/
    ├── site.yml              # the playbook
    ├── group_vars/all.yml    # every tunable knob
    └── roles/
        ├── common            # packages, timezone, auto-updates, fail2ban
        ├── php               # PHP-FPM + extensions + hardened php.ini
        ├── mariadb           # server hardening, app database and user
        ├── apache            # event MPM, FPM proxy, security headers, vhost
        ├── app               # directory layout, DB config, sample page
        └── tls               # optional Let's Encrypt certificate
```

## What you get

- A dedicated VPC and subnet — nothing lands in the default network.
- Firewall rules that open **only** 80/443 (and 22 from the ranges you list), plus a
  logged catch-all deny so blocked probes are visible.
- A Shielded VM (secure boot, vTPM, integrity monitoring) with a static external IP
  and its own least-privilege service account (`logging.logWriter`,
  `monitoring.metricWriter` — no broad project rights).
- Apache with the **event MPM** proxying PHP to **PHP-FPM** over a unix socket,
  security headers, no directory listings, no version banners.
- MariaDB bound to `127.0.0.1`, anonymous users and the `test` database removed,
  root restricted to socket login, and a dedicated application user.
- Database credentials rendered outside the document root (`0640`, group `www-data`).
- A sample landing page and a `/health.php` JSON probe that the playbook asserts on.

## Prerequisites

| Tool | Version |
|---|---|
| Terraform | ≥ 1.5 |
| Ansible | ≥ 2.15 (`ansible-core`) |
| gcloud CLI | any recent (for authentication) |
| An SSH keypair | `ssh-keygen -t ed25519` |

Authenticate once, so Terraform picks up application-default credentials:

```bash
gcloud auth application-default login
gcloud config set project MY_PROJECT
```

The account needs `roles/compute.admin`, `roles/iam.serviceAccountAdmin`,
`roles/resourcemanager.projectIamAdmin`, and — if `enable_apis = true` —
`roles/serviceusage.serviceUsageAdmin`.

## Quick start

```bash
cd infra
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
$EDITOR terraform/terraform.tfvars      # project_id + allowed_ssh_cidrs at minimum

make secrets       # generates ansible/group_vars/vault.yml with a random DB password
make deps          # installs the required Ansible collections
make up            # terraform apply, then ansible-playbook, then prints the URL
```

`make up` is just `apply` → `deps` → `provision` → `url`; run them separately if you
prefer. Other targets: `make plan`, `make check` (Ansible dry run), `make ssh`,
`make lint`, `make destroy`. `make help` lists them all.

The inventory at `ansible/inventory/hosts.ini` is **generated by Terraform** on every
apply — it is gitignored, and hand edits are lost.

## Configuration

**Infrastructure** — `terraform/terraform.tfvars`:

| Variable | Default | Notes |
|---|---|---|
| `project_id` | *(required)* | Target GCP project |
| `region` / `zone` | `us-central1` / `-a` | Zone must be inside the region |
| `machine_type` | `e2-small` | `e2-micro` fits the free tier but is tight for MariaDB |
| `boot_image` | `debian-cloud/debian-12` | Ubuntu LTS images work too |
| `allowed_ssh_cidrs` | `0.0.0.0/0` | **Narrow this** — `curl -s ifconfig.me` |
| `allowed_web_cidrs` | `0.0.0.0/0` | Public site |
| `enable_apis` | `true` | Set false if you cannot manage service usage |
| `deletion_protection` | `false` | Set true for anything long-lived |

**Server** — `ansible/group_vars/all.yml`: app paths, database name/user, PHP limits
and timezone, fail2ban toggle, TLS settings.

The database password lives in `ansible/group_vars/vault.yml` as `vault_db_password`
(gitignored). Encrypt it once you are past the first run:

```bash
ansible-vault encrypt ansible/group_vars/vault.yml
# then: cd ansible && ansible-playbook site.yml --ask-vault-pass
```

## Deploying your own code

Point `app_source_dir` in `ansible/group_vars/all.yml` at a local directory and
re-run `make provision`. Its contents are rsynced into `/var/www/lamp/public`
(deleting anything stale, excluding `.git` and `.env`), and the sample page is
skipped. Read the database credentials from `/var/www/lamp/config/db.php`:

```php
$config = require '/var/www/lamp/config/db.php';
$pdo = new PDO($config['dsn'], $config['user'], $config['password'], $config['options']);
```

## Enabling HTTPS

Point a real DNS A record at the VM's external IP (`make url`), then:

```yaml
# ansible/group_vars/all.yml
tls_enabled: true
tls_domains: ["example.com", "www.example.com"]
tls_email: "you@example.com"
app_server_name: "example.com"
app_server_aliases: ["www.example.com"]
```

`make provision` then requests a Let's Encrypt certificate, enables the renewal
timer, and the HTTP vhost starts redirecting to HTTPS (the ACME challenge path
stays on HTTP).

## Operating it

```bash
make ssh                                       # shell on the box
cd ansible && ansible-playbook site.yml -t app # re-deploy just the app
cd ansible && ansible-playbook site.yml -t db  # just the database layer
curl -s $(cd .. && make -s url)health.php      # JSON health probe
```

Tags available: `common`, `php`, `db`, `web`, `app`, `tls`.

Logs on the VM: `/var/log/apache2/lamp-{access,error}.log`, `/var/log/php-errors.log`,
`journalctl -u mariadb`.

## Notes and limits

- **Single VM, single zone.** The database lives on the web server — the classic LAMP
  shape, fine for demos, small sites and coursework. For production, move the data to
  Cloud SQL and put the VMs behind a managed instance group and load balancer.
- **State is local** by default. Uncomment the `gcs` backend in `terraform/versions.tf`
  before more than one person runs this.
- **No backups are configured.** Add a snapshot schedule or `mysqldump` cron before
  storing anything you would miss.
- `make destroy` deletes the VM, its disk and the static IP. The database goes with it.
